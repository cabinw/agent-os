① 已定的四件事

四个决策已拍板。A、C 由 ADR-007 记录；B 由 ADR-008 取代原单机范围；D 是流程决策。

决策 A ✓桌面外壳：Tauri 2

三个硬需求同时满足：原生菜单栏挂件、原生窗口 chrome、UI 用 TS 与 packages 共享事件类型。Rust 只出现在 src-tauri/，不碰领域逻辑。

承担的代价：Tauri 渲染在 WebView 里，「macOS 原生质感」是要做的设计工作而不是白拿的。滚动惯性、右键菜单、窗口行为都得专门调——排期时留出这部分，别当成 0 成本。

决策 B ✓Server Hub + Local-first Runners

Hub 是服务端控制面，只负责认证、路由、派发、事件和项目元数据；Runner 负责适配器、厂商会话和项目工作副本。Runner 主动连出，工作站不开入站端口。

实现顺序不是部署拓扑：先用 Local Runner 跑通真实 CLI 并冻结共享契约，再只替换 transport 做 Remote Runner。项目文件跨机器靠 Git remote，不靠网络盘。

决策 C ✓claude-opus-5 · adaptive thinking · effort: "high"

目标拆解、记忆摘要、脉冲头条统一用这一档。记忆摘要降到 medium 仍然是留着的省钱手段，但现在不动——混档位会让质量回归更难归因。

决策 D ✓不做 CI

GitHub Actions 砍掉。但两样东西没跟着丢：

① 重放测试本来就是 1.3 的完成判据，由 Vitest（0.2）承载，和 CI 无关，一行没少。

② 原本挂在 CI 上的 分层 grep 检查（ADR-004 的厂商名、包依赖方向）改成本地脚本 pnpm check:layers——见 0.3。它是 ADR-004/005 唯一的机械保障，不能因为砍 CI 就一起没了。想接 CI 或 pre-commit 时它是现成的。

② 技术栈选型

每一项都写了被否决的替代方案。规格里的约束（尤其是 ADR-004 和 ADR-005）淘汰掉了不少看起来更顺手的选择。

核心

语言TypeScript · Node 22+

为什么：MCP 官方 SDK 在 TS 上是一等公民；更重要的是 ADR-005 规定 UI 是 reducer 的投影——UI 和内核用同一种语言，reducer 只写一遍，类型直接共享。

否决 Swift：原生手感最好，但领域模型和 reducer 要在 Swift 里重写一遍，两份实现迟早分叉。否决 Rust：做内核很合适，但适配器生态和迭代速度不划算，而且逼着 UI 走 IPC。
桌面外壳Tauri 2

为什么：三个硬需求同时满足——原生菜单栏挂件（规格里是对等界面，不是快捷方式）、原生窗口 chrome、UI 用 TS 从而与 packages 共享事件类型。体积约 10MB。

诚实的代价：Tauri 的 UI 层是 WebView。设计语言里写的「macOS 原生质感」会变成设计工作，而不是白拿的东西——滚动惯性、控件手感都得自己调。

否决 Electron：能力相同但 150MB 起步，没有换来任何优势。否决 SwiftUI：原生手感最好，但必须在 Swift 里重实现全部 reducer——两份实现会漂移，而且漂移在投影和日志对不上之前是看不见的，这正是 ADR-005 要防的失败。完整取舍见 ADR-007。
事件存储SQLite · better-sqlite3 · WAL

为什么：Hub 是单写者。append-only 表 + 项目内单调 seq + 独立快照表，正好是 event-core 需要的全部。同步 API 让 reducer 保持纯函数；WAL 负责崩溃恢复。

暂不采用 Postgres：只有出现多个 active Hub writer 才需要重开 ADR。否决纯文件追加：排序、幂等、崩溃恢复全要自己实现，等于重写一个更差的 SQLite。
边界校验Zod · .strict()

为什么：规格明确写了「未知字段是拒绝而不是忽略」。.strict() 就是这一条的直接实现，不用自己写校验器。同一份 schema 还能推导出 TS 类型和 MCP 工具的 JSON Schema。

IDULID

为什么：规格示例里的 evt_01H... 本身就是 ULID 前缀。可按时间排序、无需协调、26 字符。

否决 UUIDv4：不可排序，事件日志里是明确的劣势。

协议与智能体

MCP@modelcontextprotocol/sdk

MCP 是 agent 参与 Agent OS 的唯一入口。它不是唤醒通道：Hub 派发由共享 Runner contract 承担，Local / Remote 的差别只在 transport。两条通道都必须经过 Hub 的认证 principal。

LLM SDK@anthropic-ai/sdk · claude-opus-5

用于 Supervisor 的目标拆解、记忆摘要、脉冲头条生成。开 thinking: { type: "adaptive" }，拆解用 effort: "high"。

注意：这是 Agent OS 自己调的模型，和「通过 MCP 接入的外部智能体」是两回事——后者永远不在核心代码里出现厂商名（ADR-004）。

Supervisor 循环Tool Runner，不是 Managed Agents

为什么这个区分重要：Managed Agents 会把 agent loop 和会话状态放在 Anthropic 侧。而 ADR-005 要求事件是唯一可写对象、状态必须能从本地日志重放。把循环托管出去，Agent OS 就失去了对自己事实来源的所有权。

用 client.beta.messages.toolRunner：SDK 提供循环，状态留在我们的日志里。它的 per-turn hook 正好是审批闸门的落点——在工具真正执行前拦下来等人。

③ 五个容易做错的关键判断

1. 先写 reducer，再写 UI

顺序反了，UI 一定会自己发明状态字段，然后你会为了迁就它在内核里加表。Phase 1 全程无 UI 是刻意的。

2. 状态转移矩阵要穷举测试

8 个状态 × 10 个事件 = 80 个格子，小到可以全测。非法转移被拒绝的用例比合法路径更重要——它是防止生命周期再次漂移的唯一保险。

3. 审批闸门要在最早期落地

它在 Phase 3 的清单里，但闸门的接口要在 Phase 1 的 MCP Server 就留好。事后加一道能阻塞调用方的闸门，比一开始就留位置贵得多。

4. 别让 provider 泄进内核

写完 Phase 1 时跑一次：grep -rE 'openai|anthropic' packages/event-core packages/task-engine。有命中就说明抽象漏了。这条可以做成 CI 检查。

5. Local first 不等于单机产品

Local Runner 是共享契约的参考实现。它跑通后 Remote Runner 只能增加认证、序列化、重连和背压，不能改派发、事件、会话或错误语义。

Hub / Runner — 从已验证 spike 到正式边界

← 现在这里

A / B / C 已证明两条通道、能力路由和任务审阅。现在沿 ADR-008 把 co-located spike 收敛成正式边界：先保护 Hub，再抽 Local Runner、冻结共享契约，最后启动 Remote Runner。

为什么现在做。spike 分别证了唤醒通道（四家都通）和参与通道（四家里三家零适配器），但从没测过把它们接起来——spike 里 to 永远是 you，人是唯一收件人。这个接缝不通，Agent OS 就只是一个多窗口聊天工具。
预检已跑，结论改了形态。原以为只有 Claude Code 能当协调者，实测 Claude Code / Kimi / Grok 三家都能，只有 Codex 不行（它得靠适配器翻译）。另外撞见一件没料到的事：Grok 通过 get_context 读到了 Kimi 半小时前留下的消息，而两个进程从没同时存在过——B 阶段的「读」那一半已经天然通了，剩下只有「写触发唤醒」。
三个同族 bug，全是真机跑出来的。每一个都是运行时信任了 agent 能控制的字段：① replyTo 不填就脱离因果链，预算失效；② 重复注册写了第二条事件，污染此后所有重放；③ 「这一轮说过话没有」按因果链判断，而任务唤醒没有真实 cause 事件，于是交付内容被回显了两遍。
共同的修法：改成按运行时自己掌握的东西判断——运行时补链、按 seq 位置判断写没写过。任何以 agent 提供的数据为准的限制都是形同虚设。
做完之后新增的两条 protocol 规则（都来自第一次真机运行）：① causedBy 归运行时所有，caller 不填就由运行时补——任何以 agent 提供的数据为准的预算都是形同虚设；② 重复注册不得再写一条事件，事件是永久的，一条重复的「加入会话」会污染此后所有重放。
协调者默认 Claude Code（已定），Kimi / Grok 当备选——三家都实测能参与，但主力固定一家能让「协调行为」这个变量保持稳定。Codex 只能当执行者。
成本要心里有数。每一跳委派都是一次上下文重建，实测约 2× 溢价（阶段 3 数据）。三跳委派的账现在能算了——hub 跑长链路时别惊讶。
