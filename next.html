Scope control

现在不要做什么，以及必须拍板什么

Runner 拓扑已经正式化；当前最容易浪费时间的方式，是绕过 Event Core 依赖顺序或再造一份事件规范。

暂时不要做

  • 不要修 spike 的 JSONL 持久化；Phase 1.2 会用 SQLite + WAL 替换。
  • 不要提前做完整 memory/retrieval；先保留不可事后恢复的 provenance 事件。
  • 不要重新引入容器、独立 Unix 用户或 credential broker；可信协作者模型已由 owner 选定。
  • 不要扩完整桌面 UI；本地与远程调用切片都只需要最小可观察面。
  • 不要把“没有 CI”当作当前阻断项；唯一手工门禁已经恢复，并须在每个任务提交前保持全绿。

Event Core 开始前要拍板

  • Event Core 校验完整领域 payload，还是只保存 opaque payload？
  • EventDraft.seq = null 与持久事件正整数 seq 的边界如何表达？
  • subject 是否始终必填；Spike 的可选字段如何迁移？
  • 29 类 payload 的必填字段以 event catalog 为唯一权威。
  • 未知事件由 parser 拒绝；reducer 对未来版本事件的兼容策略单独定义。
  • 正式 Event Store 继续采用 SQLite + WAL，不从服务器部署自动推导为 Postgres。
