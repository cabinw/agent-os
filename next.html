Scope control

现在不要做什么，以及必须拍板什么

这里最容易浪费时间的方式，是在关键拓扑还没正式化时提前铺开长期能力。

暂时不要做

  • 不要修 spike 的 JSONL 持久化；Phase 1.2 会用 SQLite + WAL 替换。
  • 不要提前做完整 memory/retrieval；先保留不可事后恢复的 provenance 事件。
  • 不要重新引入容器、独立 Unix 用户或 credential broker；可信协作者模型已由 owner 选定。
  • 不要扩完整桌面 UI；本地与远程调用切片都只需要最小可观察面。
  • 不要把“没有 CI”当作当前问题；真正的问题是唯一手工门禁现在不绿。

启动远程开发前要拍板

  • Hub v2 是 supersede ADR-007 的 scope，还是只增加一种部署模式？
  • Local Runner 与 Remote Runner 必须共享哪些请求、事件、session 和错误语义？
  • Runner 连接的身份单位是 user、host、agent，还是三者组合？
  • 服务器端 event store 是否仍用 SQLite；不要从“上服务器”自动推导成 Postgres。
  • 持久 session 的最小事件／对象是什么，如何与 vendor session id 分离？
  • Windows Runner 继续作为明确 deferred，不让它拖慢首个纵向切片。
